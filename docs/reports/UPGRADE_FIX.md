# Исправление системы улучшения в GUI версии

## Проблема
Система улучшения снаряжения не работала в GUI версии игры, так как метод `upgrade_item` использовал консольные функции `input()` и `print()`, которые несовместимы с графическим интерфейсом.

## Решение
1. **Добавлен новый метод `upgrade_item_gui()`** в класс `Inventory` ([inventory.py](inventory.py)):
   - Не использует `input()` и `print()`
   - Принимает параметр `stones_to_use` напрямую
   - Возвращает словарь с результатом операции вместо печати в консоль
   - Поддерживает режим получения информации (stones_to_use=-1)

2. **Старый метод переименован в `upgrade_item_console()`**:
   - Используется для консольной версии игры
   - `upgrade_item()` теперь вызывает `upgrade_item_console()` для обратной совместимости

3. **Обновлена GUI версия** ([gui_main.py](gui_main.py)):
   - Метод `upgrade_selected()` теперь использует `upgrade_item_gui()`
   - Добавлены диалоговые окна для выбора количества камней
   - Показывается расчёт стоимости с учётом скидки от камней
   - Подтверждение улучшения через `messagebox`

## Функциональность
- ✅ Улучшение предметов в GUI работает
- ✅ Поддержка камней улучшения (каждый даёт скидку 30%)
- ✅ Проверка наличия золота
- ✅ Автоматическое обновление экипированных предметов
- ✅ Консольная версия продолжает работать как раньше

## Тестирование
Созданы два тестовых скрипта:
- `test_upgrade.py` - базовый тест улучшения
- `test_upgrade_with_stones.py` - тест с использованием камней улучшения

Оба теста показывают корректную работу системы.

## Фильтрация и пометки силы в инвентаре (новое)

- Добавлен фильтр в GUI-инвентаре ([gui_main.py](gui_main.py#L600)) — выпадающий список с опциями: `all`, `weapons`, `armor`, `potions`, `materials`, `stronger`, `weaker`.
- Добавлен чекбокс `Показывать силу`, который добавляет пометки `[Сильнее]`, `[Слабее]`, `[Равное]` рядом с экипировкой на основании сравнения с текущей экипировкой игрока.
- Логика оценки силы реализована в `Inventory.evaluate_strength()` ([inventory.py](inventory.py#L1)) — сравнивает `attack_bonus`/`defense_bonus` с текущим экипированным предметом или с базовыми характеристиками игрока.
- GUI использует внутренний массив соответствия отображаемых индексов к реальным индексам в `inventory.items`, чтобы операции (использовать, улучшить, продать) работали корректно при фильтрации.

Эти изменения упрощают управление снаряжением: зелья и материалы можно скрыть, оставить только экипировку, или быстро найти предметы хуже/лучше текущего экипированного.
